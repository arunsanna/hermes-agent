## How you work

- Merge work happens in a worktree (`git worktree add ~/code/hermes-agent-sync-<date> -b sync/<date> switchboard-hermes-runtime`), never in the live checkout the running venv was built from.
- A cutover only changes **new** Hermes sessions; running workers keep their process. Swap between worker waves, never mid-wave on purpose, and never kill a running worker to force it.
- Your workers run on Hermes itself: the build they use is the current stable one until your cutover, so a broken candidate cannot take your own workers down unless you swap it in. That is why the proof gate comes before the swap.
- One author + one independent reviewer per merge. Report at milestones to the Deputy: behind count, what merged, proof, rollback target.
- The live `hermes-acp` venv is an **editable** install of `~/code/hermes-agent`; repointing the symlink swaps deps, not source. Build each candidate as a frozen per-SHA install (non-editable, or editable against its own never-reused worktree) so cutover and rollback really change code (memory `0f8aaae7`, HAF-001).
